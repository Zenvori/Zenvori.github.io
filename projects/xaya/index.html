xaya
换一种方式渲染。

一个快速、跨平台的 GPU 加速终端模拟器。它基于 Alacritty，并为 macOS 加入了一个原生 Metal 渲染器，同时保留 OpenGL 作为稳定的默认选项。

Why xaya

为什么做它

不重写终端，只换掉最底下那一层。

Alacritty 已经把终端该做的事做得很好：快、简洁、配置清晰。xaya 想回答的只是一个问题——在 Mac 上，直接用 Metal 画终端会怎样？

解析器、PTY、输入、字体光栅化、搜索、选择和输入法处理全部沿用原有实现，只有渲染这一层有两个后端可选。Metal 通过运行时编译的着色器工作，不需要 Swift 重写，也不需要构建期的 Metal 编译器。

它默认关闭。如果 Metal 初始化失败，或者运行中出错，窗口会自动切回 OpenGL 并重建字形缓存——终端不会因为一个实验而停下来。

Features

它能做什么

01

原生 Metal 渲染

实例化四边形绘制文字，保留 RGB 子像素抗锯齿和彩色 Emoji；下划线、波浪线等装饰与 OpenGL 版本使用相同公式。

02

自动回退

不支持 Metal 的机器、初始化失败或运行时错误，都会无缝切换到 OpenGL，并在日志里写清原因。

03

兼容 Alacritty

已有的 Alacritty 配置、terminfo 和环境变量继续可用。新配置放在 ~/.config/xaya/xaya.toml。

04

可度量

设置 ALACRITTY_RENDER_METRICS=1，退出时输出每个窗口的帧耗时、GPU 执行时间和缓冲区复用情况。

Lab notes

一份诚实的实验记录

Apple M4 Pro · 9 个 Metal 窗口 · 3 轮取中位数

字形上传 GPU 缓冲区分配

17,096 → 9

引入缓冲池和共享管线之后，同样的工作负载几乎不再新分配缓冲区。
指标OpenGLMetal
PTY 写入吞吐17.32 MiB/s17.27 MiB/s
进程 CPU 时间1.413 s1.412 s
实例缓冲区分配—244 → 12

吞吐和 CPU 时间在误差范围内持平——这些数据并不能证明 Metal 更快。输入延迟和能耗还需要专门测量，所以 Metal 目前仍标记为实验功能。

Get started

开始使用

需要 Rust 工具链。

1构建并安装

# 克隆源码
git clone https://github.com/Zenvori/xaya.git
cd xaya

# macOS：生成 xaya.app
make app
cp -r target/release/osx/xaya.app /Applications/

# 其他平台：target/release/xaya
cargo build --release

2开启 Metal（可选）

# ~/.config/xaya/xaya.toml
[debug]
renderer = "Metal"

3配置文件查找顺序

  1. $XDG_CONFIG_HOME/xaya/xaya.toml
  2. ~/.config/xaya/xaya.toml
  3. 原有的 Alacritty 配置路径

需要支持 Metal 的 Mac，macOS 10.13 或更新版本。
